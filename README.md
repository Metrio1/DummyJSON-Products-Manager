# DummyJSON Products Manager — Тестовое задание

SPA-приложение для управления товарами с формами и интеграцией с внешним API. Реализована авторизация, CRUD-операции над товарами, валидация форм и оптимистичное обновление кэша.

## Функциональность

- Авторизация с моковыми пользователями
- CRUD товаров через DummyJSON API
- Валидация форм (Yup + React Hook Form)
- Персистентность сессии (localStorage через Zustand persist)
- Оптимистичное обновление кэша при мутациях
- Обработка ошибок сети и таймаутов
- Поддержка доступности (a11y) в диалогах и формах

## Архитектурные решения

### Разделение слоёв

Приложение организовано по принципу разделения ответственности (SRP):

- **api/** — чистые функции для HTTP-запросов (Axios)
- **hooks/** — React Query обёртки для управления серверным состоянием
- **components/pages/** — UI-компоненты и страницы

Это обеспечивает чёткое разделение между логикой данных и представлением.

### Query Key Factory

В `src/api/queryKeys.ts` реализован factory для генерации ключей кэша TanStack Query. Это единый источник ключей, который используется как в `useProducts()` (чтение), так и в мутациях (создание/обновление/удаление). Такой подход предотвращает рассинхрон кэша при изменении структуры ключей в будущем (например, при добавлении пагинации или фильтров).

### Работа с DummyJSON

DummyJSON — публичное демо-API с особенностями, которые учтены в архитектуре:

- API не персистит изменения на сервере (create/update/delete возвращают мок-ответы, но не сохраняются между запросами)
- POST /products/add всегда возвращает один и тот же фиксированный ID

Для корректной работы редактирования/удаления товаров, созданных на клиенте, реализован механизм локальных ID (`src/store/localProductsStore.ts`):

1. При создании товара сервер возвращает фиксированный ID
2. Мы заменяем его на уникальный локальный ID (`generateLocalId`)
3. Локальный ID сохраняется в Zustand-сторе
4. При редактировании/удалении проверяется, является ли ID локальным — если да, реальный API-запрос пропускается, обновление происходит только в локальном кэше

Это осознанный воркэраунд под особенности демо-API, а не баг.

### Zustand vs TanStack Query

Zustand используется только для полностью клиентского состояния:

- `authStore.ts` — авторизация и персистентность сессии
- `localProductsStore.ts` — отслеживание локально созданных ID

Серверное состояние управляется исключительно через TanStack Query. Это разделение предотвращает смешивание логики и упрощает отладку.

### Валидация форм

- **Yup** — схемы валидации (описание правил в декларативном стиле)
- **React Hook Form** — управление состоянием формы и отправка
- **@hookform/resolvers** — интеграция Yup с React Hook Form

Такой подход минимизирует boilerplate и обеспечивает типобезопасность.

## Известные ограничения

- **DummyJSON** — публичное демо-API без гарантий SLA. Возможны задержки ответа или временные недоступности. UI обрабатывает такие ситуации через сообщения об ошибках и позволяет повторить операцию.
- **Персистентность данных** — изменения в существующих (не созданных локально) товарах не сохраняются на сервере между сессиями. Это ограничение самого DummyJSON, а не приложения. Локально созданные товары существуют только в рамках текущей сессии браузера.
